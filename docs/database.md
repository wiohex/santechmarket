# База, резервная копия и перенос сайта

## Что сохранять

При стандартной настройке `DATABASE_URL=sqlite:///./store.db` рабочая база — `store.db` в корне проекта. В ней товары, категории, аккаунты и заявки. Фото лежат отдельно в `uploads/`, настройки — в `.env`.

Если `DATABASE_URL` изменён, фактический путь базы может быть другим. Команда резервирования читает путь из настроек; она поддерживает только файловую SQLite-базу. PostgreSQL требует собственного резервирования.

## Сделать резервную копию

Из PowerShell в корне проекта:

```powershell
.\.venv\Scripts\python.exe -m scripts.backup
```

Команда создаёт новую папку `backups/дата_время/`. Внутри — согласованный `store.db` и копия `uploads/`. Старые копии не перезаписываются. Можно выполнять при работающем сервере: база копируется через SQLite backup API. На время копирования фото воздержитесь от редактирования товаров и загрузок.

`.env` сохраните отдельно в закрытом месте. Копия базы содержит аккаунты и контактные данные заявок: она исключена из Git вместе с папкой backups.

## Перенести на другой компьютер

1. Создайте свежую резервную копию командой выше.
2. Скопируйте папку проекта, не перенося `.venv`, кэши и `.runtime`. Секреты `.env` передавайте отдельно и только владельцу.
3. На новом компьютере установите Python и создайте `.venv`, установите зависимости по README.
4. Пока сайт на новом компьютере **остановлен**, положите `store.db` из резервной копии в корень проекта, а `uploads/` — рядом.
5. Настройте `.env` на новом компьютере. Для стандартной SQLite используйте `DATABASE_URL=sqlite:///./store.db`. Для новой установки можно создать новый SECRET_KEY; старые сеансы входа тогда не сохранятся.
6. Выполните `.\.venv\Scripts\python.exe -m alembic upgrade head`.
7. Запустите START.cmd. Проверьте вход владельца, товары, фотографии и заявки.

Учётные записи уже находятся в перенесённой базе. Не запускайте create_admin с тем же email. Seed с демо-товарами при переносе не нужен.

## Восстановить резервную копию на этом компьютере

Восстановление заменит текущее состояние базы состоянием выбранной копии. Сначала сделайте ещё одну копию текущих данных.

1. Остановите **все** процессы этого сайта. Если запускали через START.cmd — Ctrl+C в окне сервера. Если сайт был запущен ранее в фоне, сначала завершите именно тот сервер; закрытие вкладки браузера сервер не останавливает.
2. Убедитесь, что http://127.0.0.1:8000 больше не открывается после обновления.
3. Переместите текущие `store.db`, `store.db-wal`, `store.db-shm` (если есть) и `uploads/` в отдельную папку вне корня. Сохраните их вместе. Не смешивайте старые WAL/SHM с восстановленной базой.
4. Скопируйте выбранный `backups/дата_время/store.db` в корень под именем `store.db`, а папку `uploads/` — рядом.
5. Выполните `.\.venv\Scripts\python.exe -m alembic upgrade head` и запустите сайт.
6. Проверьте товары, фото и заявки. `.env` не заменяйте, если его настройки подходят.

Не копируйте только рабочий store.db при запущенном сервере: последние изменения могут находиться в WAL. Используйте команду backup.

Произвольная чужая `.db` или `.sql` не совместима со схемой этого приложения. Для неё сначала нужна выгрузка товаров в [Excel/CSV](import-products.md).
