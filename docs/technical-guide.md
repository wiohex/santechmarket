# СантехМаркет — техническое руководство

Для ежедневного запуска начните с [README](../README.md). Импорт: [import-products.md](import-products.md). Перенос и резервирование: [database.md](database.md).

Оптовые поставки сантехники в магазины: открытый каталог, заявки без онлайн-оплаты, кабинет магазина и админка. Все цены предварительные и не включают доставку; стоимость и условия доставки менеджер согласует отдельно по телефону. Python 3.11+, FastAPI, Jinja2, чистые CSS/JS, SQLAlchemy, Alembic. Проверено на Windows и Python 3.14.

## Запуск в Windows PowerShell

Откройте терминал в папке проекта. Активация venv не обязательна:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.init_env
notepad .env
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m scripts.seed
.\.venv\Scripts\python.exe -m scripts.create_admin
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Откройте http://127.0.0.1:8000 . Вход владельца: `/login`, панель: `/admin`. Команды выполняются из корня проекта. Остановка — Ctrl+C. Если порт занят, укажите `--port 8001`.

`scripts.init_env` создаёт случайный секрет, не выводит его и не перезаписывает существующий `.env`. В этой рабочей копии `.env` и локальный администратор уже созданы: для входа используйте `ADMIN_EMAIL` и `ADMIN_PASSWORD` из `.env`; повторно создавать его не нужно. Демо-прайс содержит 12 товаров в 6 категориях. Цены, описания и иллюстрации демонстрационные. Реальные фото можно загрузить в админке. Seed повторно не меняет существующие товары.

## Настройки `.env`

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | Случайная строка от 32 символов; смена завершает текущие сессии |
| `DATABASE_URL` | По умолчанию `sqlite:///./store.db` |
| `ADMIN_LOGIN` | Optional owner login alias; email login also works |
| `ADMIN_EMAIL` | Email создаваемого владельца, по умолчанию `owner@example.com` |
| `ADMIN_PASSWORD` | Необязательно: пароль для создания владельца; если пусто, скрипт запросит его скрытым вводом |
| `COOKIE_SECURE` | `false` для локального HTTP; `true` при размещении через HTTPS |
| `ALLOWED_HOSTS` | Имена хостов через запятую; для сервера добавьте свой домен без протокола |
| `STORE_NAME` | Название магазина |
| `STORE_PHONE` | Контактный телефон |
| `STORE_ADDRESS` | Фактический адрес |
| `STORE_HOURS` | Часы работы |
| `STORE_MAP_URL` | HTTPS-ссылка на виджет Яндекс Карт, например `https://yandex.ru/map-widget/v1/?...`; обычная ссылка на карту для iframe не подходит |
| `TELEGRAM_BOT_TOKEN` | Токен бота, необязательно |
| `TELEGRAM_CHAT_ID` | ID личного чата или группы владельца, необязательно |

Без адреса и карты страница честно показывает заглушки. Не публикуйте `.env`, базу и содержимое `uploads/`: они исключены из Git. После изменения окружения перезапустите приложение.

## Создание владельца

Укажите `ADMIN_EMAIL`, запустите `python -m scripts.create_admin` через venv. Если `ADMIN_PASSWORD` пустой, введите пароль дважды в терминале. Для владельца допустимо от 3 до 128 символов; для регистрации компаний — от 10. Пароли сохраняются как Argon2id-хеши. Скрипт не перезаписывает и не повышает роль уже существующего пользователя с таким email. После создания можно убрать `ADMIN_PASSWORD` из `.env`: вход продолжит работать по сохранённому хешу.

## Как пользоваться

- Магазин без регистрации: каталог → добавление товаров → `/request` → имя, телефон, комментарий → номер заявки. Можно менять количество и удалять позиции. Если товар не найден — `/quick-request`.
- Магазин с кабинетом: `/register` → данные компании и корректный ИНН → кабинет. Заявки, отправленные после входа, появляются в истории. Гостевые заявки автоматически к компании не привязываются.
- Повтор заявки заменяет текущий список, берёт актуальные цены и пропускает архивные товары. Перед созданием новой заявки клиент проверяет список и отправляет форму. Повтор текстовой заявки копирует её текст.
- Владелец: `/admin` → фильтр и карточка заявки → статус и комментарий. Комментарий владельца виден компании в кабинете.
- `/admin/products`: создание, изменение, фото и скрытие товара. Скрытие сохраняет историю заявок. Для восстановления отметьте «Показывать в каталоге» в редакторе.
- `/admin/categories`: создание, переименование, удаление пустой категории. Категорию с товарами, в том числе архивными, сначала нужно освободить.

Цены в заявках сохраняются снимком, поэтому редактирование каталога не меняет прошлые заявки. Сумма предварительная, включает только товары. Доставка в неё не входит; стоимость и условия доставки менеджер согласовывает отдельно по телефону. Автоматического расчёта доставки нет. Повторное нажатие отправки одной формы не создаёт дубль. История компании и админка защищены ролью; гостевое подтверждение доступно по случайному секретному URL, который не следует пересылать посторонним.

## Импорт прайса

1. Войдите владельцем и откройте `/admin/import`.
2. Загрузите CSV или `.xlsx`, нажмите «Проверить файл».
3. Просмотрите результат и подтвердите импорт. До подтверждения каталог не меняется. При ошибке любой строки изменения не применяются.

Пример: `app/static/price-example.csv`, также доступен для скачивания в форме импорта.

```csv
sku;name;category;price;in_stock;description
MIX-001;Смеситель для кухни;Смесители;2490.00;1;Высокий излив
PIPE-020;Труба 20 мм;Трубы;95.50;1;Цена за метр
```

Обязательны `sku`, `name`, `category`, `price`; необязательны `in_stock`, `description`. Названия столбцов — как в примере. CSV: UTF-8 (с BOM или без) либо Windows-1251, разделитель запятая или точка с запятой. При десятичной запятой используйте разделитель `;`. XLSX: первый лист, одна строка заголовков, без объединённых ячеек; формулы замените значениями. Старый `.xls` сохраните как `.xlsx`.

Лимит: 2 МБ и 1000 товаров. В XLSX максимум 1001 физическая строка вместе с заголовком и пустыми строками; превышение отклоняется целиком. Артикулы внутри файла должны быть уникальными. Цена — неотрицательное число до 100 млн рублей и до двух знаков после запятой. Наличие: `1/0`, `да/нет`, `true/false`, `yes/no`. Неизвестные категории создаются. Товары обновляются по точному совпадению артикула, становятся активными; фото сохраняется. Без `in_stock` ставится «в наличии», без `description` описание очищается. Товары, которых нет в файле, не меняются. Перед импортом рабочего прайса сохраните резервную копию БД.

Фото: JPG/PNG/WebP, до 3 МБ и 20 млн пикселей. Проверяются расширение, MIME и содержимое, затем изображение заново кодируется в JPEG до 1600×1600 без исходных метаданных. Суммарный размер POST-запроса ограничен 6 МБ. Старые файлы при замене фото остаются в `uploads/`; очистку неиспользуемых файлов этот MVP не выполняет.

## Telegram

Создайте бота через BotFather, укажите токен и ID чата в `.env`. В личном чате сначала нажмите Start; для группы добавьте бота с правом отправлять сообщения. Перезапустите приложение и отправьте пробную заявку.

Уведомление содержит номер, контакты и состав заявки. Отправка идёт после успешного сохранения, с таймаутом 5 секунд. Ошибка отображается в серверном логе без токена; заявка остаётся в админке. Без обеих переменных отправка отключена. Автоматических повторов и гарантированной очереди уведомлений в MVP нет. Email-уведомления не реализованы: выбран предусмотренный заданием вариант Telegram.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m alembic check
```

Тесты используют отдельные временные БД и файлы, не отправляют реальные Telegram-сообщения. Покрыты создание и дубли заявок, снимки цен, CSRF, XSS-экранирование, регистрация/вход, роли, чужие заявки, сессии, лимит входа, импорт CSV/XLSX, фото и сбой уведомления. `requirements.lock.txt` фиксирует проверенное окружение; для воспроизведения используйте `pip install -r requirements.lock.txt`.

## Структура

`app/db` — подключение и сессии БД; `models` — таблицы; `schemas` — серверная валидация; `routers` — HTTP; `services` — создание заявок, импорт, обработка фото и уведомления; `templates` — Jinja2; `static` — локальные стили, JS и демонстрационные SVG. `migrations` — Alembic; `scripts` — настройка, seed и создание владельца; `tests` — pytest.

## Размещение и PostgreSQL

Для небольшого магазина запускать один worker. Лимиты попыток хранятся в памяти процесса и сбрасываются при перезапуске; для нескольких процессов вынесите их в Redis или reverse proxy. Поиск учитывает кириллицу через Python casefold и рассчитан на небольшой каталог.

Для публичного размещения настройте HTTPS/reverse proxy, `COOKIE_SECURE=true`, домен в `ALLOWED_HOSTS`, постоянное хранилище БД/фото и резервное копирование. Запускайте без `--reload`. Заполните реальные контакты и каталог. Настройки юридических текстов и публикация в хостинг не входят в эту локальную реализацию.

Для новой PostgreSQL-базы установите `psycopg[binary]`, укажите `DATABASE_URL=postgresql+psycopg://user:password@localhost/store` и выполните `alembic upgrade head`. Это создаёт пустую схему, существующие SQLite-данные автоматически не переносятся. Модели и миграция используют совместимые типы, но живой PostgreSQL в этой сессии не проверялся.

Бэкап SQLite выполняйте при остановленном приложении либо через SQLite backup API; храните также каталог `uploads/`. Даты хранятся в UTC. В MVP нет онлайн-оплаты, расчёта или оформления доставки и интеграции с 1С.
